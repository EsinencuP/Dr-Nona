# Public interface copy cleanup

The owner requested removal of small decorative overlines throughout the site and temporary editorial explanations before a future public deployment.

Removed the `eyebrow` markup and its shared `SectionHeading` prop across the home, catalogue, product, formula, about, selection, contact, document and generic content pages in RU/RO. Removed duplicate home promotion labels and the generic product-image caption/brand kicker. Product categories, millilitre volumes, search counts, headings, navigation and form feedback remain functional.

The catalogue introduction and popularity-snapshot explanation were removed from the public interface. Popularity sorting still uses the existing data/fallback policy; no CRM or ranking behavior changed. The catalogue header now has one column without an empty description column. The product image stage now has one row without a caption strip.

Removed the generic unpublished-information placeholder. When no approved Moldova documents exist, the certificates page offers a localized link to the existing contact page to request documents, without displaying an empty certificate panel or implying approval.

Product detail pages no longer synthesize an “About the product” paragraph from the product name, category, ingredients and usage when the published description is absent. Existing publishable source descriptions remain complete, and separate ingredient/usage sections remain available. The empty overview article is omitted. This removes repetitive template copy without publishing blocked claims or inventing descriptions.

Graph scope: `CatalogPage`, shared `SectionHeading` and its home/product callers, `AboutPages` and its route wrappers, `ApplicationForm` and its unit/integration coverage. These are presentation changes with no browser persistence, API, CRM, database, contact/consent or publication-status changes. The canonical merged graph is refreshed after implementation.

Relevant verification: catalogue search/filter/sort and RU/RO copy tests, route smoke coverage for twelve public pages per language on desktop/mobile, product information layout, form/navigation tests, responsive contracts and refreshed catalogue screenshots. Repository, architecture, TypeScript, ESLint, unit and build checks are required. Existing release blockers remain authoritative; deleting placeholder copy does not approve production release.

During validation, Vite's filesystem watcher crashed with `EBUSY` on a transient graph-extraction cache file. The dev watcher now excludes generated `artifacts`, `graphify-out`, `test-results` and `playwright-report` directories while continuing to watch application source. The cross-repository graph script now clusters inside its scratch directory and copies the actual clustered output only after success. This avoids comparing a complete rebuilt graph against the prior larger graph after real helper removals. The five removed graph symbols were verified to be the deleted description-template helpers/types; catalogue and CRM namespaces remain present. The refreshed map has 2,689 nodes, 5,838 links and 157 communities. The pre-existing 180 extraction-schema warnings remain.

Final results: repository hygiene under Node 22.23.1, architecture, TypeScript, ESLint, all 212 unit tests and the complete build passed. The affected browser coverage totals 93 distinct passing tests: 74 page/locale/claim/selection/accessibility cases (72 passed in the main rerun and the two corrected category fixtures passed on a focused rerun), 17 responsive/visual contracts and two product-design regressions. The fixtures distinguish FAYA's absent published composition/usage from products with available factual copy; no missing text is invented to satisfy a test. The seven Windows catalogue baselines were refreshed and then verified without snapshot updates. Desktop/mobile catalogue and RU/RO product renders were inspected. The local catalogue returned HTTP 200 after the graph refresh and watcher fix. `release:check` remains blocked by the same six open P0/P1 items.
