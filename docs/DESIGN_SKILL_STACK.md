# Dr. Nona Website — Design Skill Stack

Status: Active methodology  
Last updated: 2026-07-26

## Зачем существует этот документ

Скиллы не заменяют решения пользователя и не являются генератором случайных
идей. Они разделены по ролям, чтобы каждый следующий дизайн-артефакт проходил
одинаковые проверки и не скатывался в типичный AI-wellness шаблон.

Приоритет всегда такой:

1. последнее решение пользователя;
2. `MASTER_DESIGN_FOUNDATION.md`;
3. подтверждённый официальный материал Dr. Nona;
4. правила активного skill stack;
5. предложения, явно помеченные как PROPOSAL.

## Активное ядро

| Skill | Роль в проекте | Что берём | Что не разрешаем ему навязать |
|---|---|---|---|
| `design-taste-frontend` | главный anti-slop и visual-taste фильтр | контролируемую вариативность, продуктовую композицию, запрет generic AI-паттернов | собственную палитру или структуру вместо пользовательского брифа |
| `frontend-design` | цельность арт-дирекшна | один сильный визуальный язык, выразительную типографику, осмысленную композицию | код на discovery-стадии и эффектность вместо доступности |
| `platform-design` | UX платформы | последовательность, системность, предсказуемые сценарии | dashboard-паттерны, неуместные для бренд-каталога |
| `design-brief` | контроль полноты входных данных | фиксацию аудитории, ощущений, приоритетов и ограничений | generic default palette из закрытого словаря |
| `ui-ux-pro-max` | UX/accessibility и системная проверка | контраст, responsive, touch targets, навигацию, эвристики | шаблонный стиль вместо собственного Dr. Nona арт-дирекшна |
| `reference-design-contract` | трассируемость решений | Keep / Change / Do not copy, единый контракт и handoff | буквальное клонирование официального сайта |

## Системные скиллы

| Skill | Роль |
|---|---|
| `design-system` | трёхслойные tokens: primitive → semantic → component; единые состояния тем |
| `design-md` | поддержка `DESIGN.md` как рабочего источника визуальных правил |
| `design` | маршрутизация между брендом, токенами, UI и будущими артефактами |
| `design-consultation` | kickoff-проверка полноты системы и качества решений |
| `color-expert` | цветовая и contrast-проверка Mineral Light и Lord |
| `ui-skills` | компактные единые UI-ограничения для всех компонентов |

Некоторые локальные `design-md`, `design-consultation`, `color-expert` и
`ui-skills` являются catalogue-entry скиллами: они описывают назначение, но не
содержат полный upstream bundle. Поэтому они используются как методологические
маршрутизаторы и не выдаются за запущенный полный внешний workflow.

## Craft и anti-slop аудит

| Skill | Применение |
|---|---|
| `make-interfaces-feel-better` | концентрические радиусы, оптическое выравнивание, мягкая глубина, читаемость, интерактивные зоны |
| `emilkowalski-motion` | единый сдержанный язык micro-interactions и reduced-motion |
| `high-end-visual-design` | проверка на дешёвые default fonts, грубые тени, шаблонные сетки и небрежную детализацию |
| `gpt-taste` | проверка на повторяемые AI-композиции, узкие многострочные hero и бессмысленные meta-labels |

`high-end-visual-design` и `gpt-taste` применяются только как аудиторы. Их
предписания о гигантских отступах, обязательных bento, glass, GSAP, AIDA,
постоянных scroll-сценах и случайной генерации не являются правилами Dr. Nona,
поскольку противоречат утверждённой рабочей плотности, зрелой аудитории и
требованию не додумывать дизайн.

## Скиллы следующих стадий

Эти скиллы релевантны, но не запускаются до появления соответствующего
артефакта:

| Стадия | Skills | Условие активации |
|---|---|---|
| Wireframe / static visual | `design-review`, `plan-design-review`, `high-end-visual-design` | есть статичный макет или согласованная схема страницы |
| Prototype motion | `emilkowalski-motion`, `review-animations`, при необходимости GSAP skills | сначала утверждён статичный layout |
| Frontend implementation | `frontend-design`, `ui-skills`, `web-design-guidelines`, `make-interfaces-feel-better` | пользователь явно разрешил код |
| Browser QA | `design-review`, `web-design-guidelines`, `ui-ux-pro-max` | существует работающий preview |
| Reference refresh | `web-reference-analyzer` | официальный сайт изменился или нужен новый source audit |

## Binding synthesis

Все скиллы вместе дают не «максимум эффектов», а максимум независимых проверок.
Для Dr. Nona обязательна следующая синтезированная позиция:

- наука и доверие важнее декоративного wow;
- уникальность строится композицией, реальными материалами и брендовым ритмом;
- каталог использует пространство функционально;
- округлость мягкая и системная, не детская;
- motion сообщает состояние и не расходует ресурс без причины;
- бело-голубая Mineral Light тема остаётся основной;
- Lord является редким, полным и осмысленным тематическим переключением;
- ни один скилл не может добавить страницу, текст, продукт или факт без
  утверждённого источника.

## Skill quality gate

Перед утверждением любого будущего экрана проверить:

- [ ] Решение прослеживается до пользовательского брифа или источника.
- [ ] Экран нельзя без изменений перебрендировать под другой wellness-бренд.
- [ ] Halo Complex™ и фактический контент не теряются за декором.
- [ ] Зрелая аудитория понимает структуру без обучения.
- [ ] Нет generic AI glow, glass, beige-luxury или одинаковых feature cards.
- [ ] Плотность соответствует типу страницы.
- [ ] Lord не превращён в случайную тёмную секцию.
- [ ] Цвет, радиусы, типографика и motion используют одну систему.
- [ ] Reduced motion, contrast, keyboard и touch requirements учтены.
